# `skills` CLI grouping research

Checked against `skills` CLI `1.5.23` at commit [`435076e`](https://github.com/vercel-labs/skills/tree/435076e78988e1e6ec40d00b0b1d76bdbbc5419a) and `mattpocock/skills` at commit [`6654f6b`](https://github.com/mattpocock/skills/tree/6654f6b60cd9d5be8b54c6fafe44346dabeb3b76) on 2026-08-27.

## Finding

`skills.sh.json` and the `npx skills` picker are separate surfaces.

- `skills.sh.json` controls only the sections on a repository page on skills.sh. The official documentation explicitly says it does not change CLI installation behavior. ([Customize repo pages](https://www.skills.sh/docs/customize))
- The CLI derives picker groups from Claude plugin manifests. It reads `.claude-plugin/plugin.json` as one plugin and `.claude-plugin/marketplace.json` as a catalog of multiple plugins, then maps each explicitly listed skill path to the corresponding plugin name. ([manifest reader](https://github.com/vercel-labs/skills/blob/435076e78988e1e6ec40d00b0b1d76bdbbc5419a/src/plugin-manifest.ts#L114-L182))
- Once any mapped skill exists, the interactive `add` picker renders plugin names as title-cased section headings and assigns discovered but unmapped skills to an automatic `Other` group. With no mapped skills, the picker stays flat. ([interactive picker](https://github.com/vercel-labs/skills/blob/435076e78988e1e6ec40d00b0b1d76bdbbc5419a/src/add.ts#L1328-L1357))
- `npx skills add --list` calls its ungrouped remainder `General`, not `Other`. ([non-interactive list output](https://github.com/vercel-labs/skills/blob/435076e78988e1e6ec40d00b0b1d76bdbbc5419a/src/add.ts#L1250-L1288))

## What each manifest can express

`.claude-plugin/plugin.json` has one `name` and one explicit `skills` array. It therefore creates one named group; any other skills found by normal discovery remain ungrouped and appear as `Other` in the interactive picker.

`.claude-plugin/marketplace.json` has a `plugins` array. Each local entry can supply its own `name`, `source`, and explicit `skills` paths, so several entries can create several named picker groups. This is not neutral display metadata: it adopts the Claude Code plugin marketplace model to define the groups. The CLI source describes the two files as a multi-plugin catalog and a single root plugin respectively. ([manifest types and discovery](https://github.com/vercel-labs/skills/blob/435076e78988e1e6ec40d00b0b1d76bdbbc5419a/src/plugin-manifest.ts#L22-L45), [group mapping](https://github.com/vercel-labs/skills/blob/435076e78988e1e6ec40d00b0b1d76bdbbc5419a/src/plugin-manifest.ts#L120-L182))

## Why Matt Pocock's install shows two sections

At the checked commit, `mattpocock/skills` contains 37 `SKILL.md` files. Its root `plugin.json` names the plugin `mattpocock-skills` and explicitly lists 25 skill paths. ([plugin manifest](https://github.com/mattpocock/skills/blob/6654f6b60cd9d5be8b54c6fafe44346dabeb3b76/.claude-plugin/plugin.json#L1-L47), [skill tree](https://github.com/mattpocock/skills/tree/6654f6b60cd9d5be8b54c6fafe44346dabeb3b76/skills))

The picker therefore shows:

```text
Mattpocock Skills  25 explicitly mapped skills
Other              12 discovered but unmapped skills
```

`Other` is generated by the CLI; it is not a second section declared by Matt's manifest. Matt's `marketplace.json` contains one entry pointing to the repository root without an explicit `skills` array, so it does not define additional group membership. ([marketplace manifest](https://github.com/mattpocock/skills/blob/6654f6b60cd9d5be8b54c6fafe44346dabeb3b76/.claude-plugin/marketplace.json#L8-L21))

The counts were checked from the pinned repository checkout with:

```sh
rg --files -g 'SKILL.md' | wc -l
jq '.skills | length' .claude-plugin/plugin.json
```

The remainder is `37 - 25 = 12`.

## Decision for this repository

Keep the CLI's default flat picker. Do not add `.claude-plugin/plugin.json` or `.claude-plugin/marketplace.json` merely to create visual sections. Retain `skills.sh.json` as the owner of web-page grouping, with the README organized to match it.

Use `docs/` for research notes. A directory does not become an installable skill by name alone: CLI discovery looks for directories containing `SKILL.md`, including during its recursive fallback. This directory contains no `SKILL.md`, so `_docs/` is unnecessary. ([CLI discovery rules](https://github.com/vercel-labs/skills/blob/435076e78988e1e6ec40d00b0b1d76bdbbc5419a/README.md#L400-L494))

Local verification with `DISABLE_TELEMETRY=1 npx -y skills@1.5.23 add . --list` found the repository's 20 public skills in one flat list and did not include `docs/`.
